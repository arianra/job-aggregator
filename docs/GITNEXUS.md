# GitNexus Code-Intelligence Integration

**Status:** active · **Tool:** `gitnexus` **1.6.9** (npm, installed globally in WSL) · **License:** PolyForm Noncommercial 1.0.0 (fine for this personal/local repo; not for a commercial product without a paid license)

GitNexus indexes this repo into a **code knowledge graph** (symbols, call chains, dependencies, execution
flows, functional clusters) and exposes it to AI agents via **MCP** plus CLI tools. It is the *code* side of
the knowledge-graph story — the *notes* side lives in the Obsidian Atlas vault. It is **local-only**: no code,
index, or metadata ever leaves WSL.

## What GitNexus wrote into this repo (and what to commit)

| Path | What it is | Commit? |
|---|---|---|
| `.gitnexus/` | The per-repo **index** (graph DB + FTS). Regenerated by `gitnexus analyze`. | **Never** (gitignored) |
| `.claude/skills/gitnexus/` | Agent skills (exploring, debugging, impact-analysis, refactor, guide, cli) for Claude Code. | Optional (agent-local) |
| `AGENTS.md` / `CLAUDE.md` | A GitNexus **awareness block** appended (hash-managed) that tells agents the knowledge graph exists and how to query it. | Yes |
| `.gitnexusrc` | Per-repo `analyze` config (currently pins `defaultBranch: master`). | Yes |

`~/.gitnexus/registry.json` (global, outside the repo) registers the index so the MCP server can serve it.

## Everyday commands (run from repo root, in WSL)

```bash
gitnexus analyze                  # build / refresh the index; re-run after meaningful code changes
gitnexus analyze --embeddings     # opt-in semantic vectors (slower, better search); default is off
gitnexus status                   # index freshness against the working tree (staleness check)
gitnexus list                     # repos the MCP server can serve
gitnexus clean                    # delete this repo's index
gitnexus detect-changes           # map your uncommitted diff → affected symbols/processes
gitnexus mcp                      # start the MCP server over stdio (agents connect via editor config)
gitnexus serve                    # backend for the browser Web UI (gitnexus.vercel.app) over local HTTP
```

## How agents use it (the MCP surface)

- `impact` — blast radius of a symbol before you edit it ("what calls `UserService.validate`?")
- `context` — 360° view of one symbol (callers, callees, which execution flows it belongs to)
- `trace` — shortest path between two symbols
- `detect_changes` / `detect-impact` — pre-commit change analysis mapped onto the graph
- `query` / `cypher` — hybrid search or raw graph queries
- `generate_map` — architecture doc with mermaid diagrams, straight from the graph

Because structure is **precomputed at index time**, agents get complete context in one tool call instead of
chaining several searches — small/cheap models included.

## Re-index discipline

- `.gitnexusrc` pins `defaultBranch: master` (this repo's default is **master**, not main) so generated
  regression examples stay correct.
- **Skill files are regenerated on every `analyze --skills` run** and the AGENTS/CLAUDE awareness blocks are
  hash-managed between `<!-- gitnexus:start -->` / `<!-- gitnexus:end -->` — do **not** hand-edit inside those
  markers; edit outside them.
- Indexing outpaces the working tree only if you change code without re-running `gitnexus analyze`;
  re-run before agent work that depends on recent structure.

## Setup & constraints (from the day we installed it)

- **Install:** `GITNEXUS_SKIP_OPTIONAL_GRAMMARS=1 ONNXRUNTIME_NODE_INSTALL=skip npm install -g gitnexus@latest`
  (global install avoids the npm-11 `npx` arborist bug; the two env vars skip unneeded grammars — Dart/Proto/
  Swift/Kotlin — and the flaky onnxruntime CUDA postinstall. Node 24, WSL Ubuntu).
- **`gitnexus doctor`** verifies native bindings (LadybugDB + FTS + vector) load on this host.
- **Embeddings are optional** and off by default; we don't enable them (`--embeddings` would also want the
  onnxruntime stack for local vector search).
